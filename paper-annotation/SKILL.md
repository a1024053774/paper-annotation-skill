# 论文双栏批注

仅在用户点名时使用。产物是一个 `.html` 文件，让读者一边读原文一边看清论文的论证结构：每段在说什么、在论证链里起什么作用、哪里论证得巧、哪里站不住。

做法是内容和页面分开：你只写 `paper.json`（原文、译文、高亮、批注、总览），`scripts/build.py` 校验后套用 `assets/template.html` 生成页面。不要手写 HTML，也不要改模板来适配某一篇论文。

不可违反：

1. **原文逐字保留。** 页面上的英文是论文原句，不改写、不合并段落、不纠正作者的用词。高亮的 `text` 必须是该段原文里逐字出现的片段，脚本会校验。
2. **不跳段。** 正文每一段都要有原文、译文和批注。篇幅长就按章节分文件写（见下），不能用"以下各段类似"之类的话带过，也不能把几段压成一段摘要。确实不收的部分（参考文献、致谢、附录）在交付时列出来。
3. **批注要有出处。** "可疑之处"只在原文里确有可指的问题时才写，并说清问题在哪一句；找不到就留空。不为了每段都有批评而编造漏洞，也不把论文没说的话算到作者头上。
4. **构建通过才算完成。** `build.py` 报错时修数据，不绕过校验；交付时如实转述覆盖率和未覆盖片段。

## 流程

1. **拿到全文，存成 `source.txt`。** PDF 用 `pdftotext -layout` 或 Read 工具逐页读；网页或粘贴的文本直接保存。抽取结果很少能直接用：分栏排版的论文里，正文会和页眉页脚、表格单元格、专栏、醒目引文交错在一起，跨页的段落被拦腰截断，上下标被压平（β 的 n 次方变成 βn），首字下沉的字母和后文分开。对照 PDF 页面把 `source.txt` 整理成阅读顺序、一段一行，修正这些抽取错误，并把不属于正文的部分（题名块、页眉页脚、参考文献）移到文件末尾而不是删掉，这样覆盖率才反映真实情况。`source.txt` 是之后核对的依据，页面上的英文原文都从它来。用户只给了摘要或片段时，先说明只能做这一部分，再继续。
2. **通读一遍再动笔。** 先定下三件事：论文体裁（决定五类高亮各自指什么，见 [references/analysis-guide.md](references/analysis-guide.md)）、全文论证骨架、术语表（同一术语全文同一译法）。批注里的"逻辑角色"要靠这副骨架才写得出来，逐段边读边写会变成复述。
3. **写 `paper.json`。** 字段见 [references/schema.md](references/schema.md)。段落的英文原文不用手打：每个段落块写 `from`，值是该段开头的几个词，脚本从 `source.txt` 里取出以它开头的那一整段。所以 `source.txt` 里一段要占一行，段与段之间空一行；某个 `from` 对上了零段或多段时，构建会报错并说明对上了几段。正文超过约 30 段时，每个章节单独存成一个 JSON 文件，在 `sections` 里写文件名，一次只写一节。
4. **构建并核对。**

   ```bash
   python3 <skill目录>/scripts/build.py paper.json -o <论文短名>.html --source source.txt
   ```

   `ERROR` 必须改到没有。`WARN` 逐条判断：`source not covered` 列出原文里没有收进页面的长片段，是参考文献、页眉页脚、作者信息就可以不管，是正文就补上；高亮占比过高就删减。
5. **打开页面看一眼。** 有浏览器工具时在桌面宽度和手机宽度各看一次，确认栏对齐、高亮可读、总览里的段落链接能跳转。
6. **交付。** 给出 HTML 路径，并说明：收录了多少节多少段、覆盖率、没有收录的部分、哪些地方因为原文抽取质量存疑。

## 写作要求

**译文。** 意译，读起来像中文学术论文；可以按中文语序重组句子，但不增删论断，保留否定、限定条件和不确定的语气（may、suggest、to some extent 不能译成肯定句）。术语首次出现时在译名后括注英文。译文里不加高亮。人名、机构名没有通行译名时保留原文。

**高亮。** 只标承载论证的词句，一段通常 1 到 3 处，可以一处都没有；脚本在高亮超过段落六成时警告。五类的判定标准和各体裁下的对应关系见 [references/analysis-guide.md](references/analysis-guide.md)。

**批注。** 每段两项必填、两项选填：

- `function`（必填）：段落功能，一个短标签，如"引出问题""界定概念""提供证据""反驳异议""小结过渡"。
- `role`（必填）：这段在整条论证链里的位置，要提到它承接哪段、为哪段铺垫，或者支撑的是哪个论点。只复述段落内容不算。
- `technique`（选填）：值得学的论证手法。
- `doubt`（选填）：可疑之处，受上面第 3 条约束。

**总览。** `skeleton` 按问题、论点、证据、反驳、结论的顺序写（实证论文可以换成问题、假设、方法、结果、讨论），每一环用 `refs` 指回对应段落；`claim` 是作者核心主张的一句话版本；`strongest` 和 `weakest` 各一条，都要用 `ref` 指到具体段落。

**图表、公式、引文。** 图和表用 `figure` 块：有 PDF 时把图表本身截成图片嵌进页面（见下），再配原图注和译文；不凭记忆重画图，也不手抄表格里的数字。图表承担论证作用时（主要结果、模型结构）给它写批注，说明它支撑的是哪一段的哪个说法。独立成行的公式用 `style: "formula"` 原样保留。大段引文用 `style: "quote"`。脚注并入它所属的段落之后，作为单独一段。

## 截取图表

```bash
python3 <skill目录>/scripts/figure.py paper.pdf --page 3 -o page3.png
python3 <skill目录>/scripts/figure.py paper.pdf --page 3 --clip 0.2,0.08,0.8,0.52 -o fig1.png
```

先导出整页并用 Read 工具看图，估出图表在页面上的位置，再用 `--clip 左,上,右,下`（占页面宽高的比例，左上角为 0,0）截取。截完再看一眼：图要完整，不带图注和正文（图注在页面上另有文字版）。把文件名写进 `figure` 块的 `image` 字段，构建时图片以 base64 嵌入，产物仍是单个 HTML。没有 PDF（只有粘贴的文本）时省略 `image`，只收图注。

## 边界

- 页面收录论文全文和图表，是给用户自己研读用的。论文不是开放许可（如 CC BY）或公有领域时，提醒用户不要公开发布生成的页面。

- 默认处理英文论文、输出中文。其他语种的原文也可以按同样结构做，但字体和核对脚本只针对拉丁字母文本调过。
- 页面的 Lora 和 IBM Plex Sans 从 Google Fonts 加载，离线时回退到系统衬线和无衬线字体，版式不变。
- 用户没提供课程信息时不要编，`meta.course` 留空即可。
